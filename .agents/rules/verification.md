# 검증·보고 규칙

- `.agents/PROJECT.md`에 기록된 명령과 실제 프로젝트 설정을 대조한 후 변경 범위에 맞는 검증을 실행한다.
- 동작 변경·버그 수정은 기존 테스트를 우선 사용한다. 회귀 위험이 있으면 원래 문제를 드러내는 테스트를 추가한다. 단순 문구·설정 변경에 구현을 그대로 복사한 테스트를 만들지 않는다.
- 실패한 검증은 원인과 영향 범위를 확인한다. 검증을 통과시키기 위해 단언을 약화하거나 실패를 숨기지 않는다.
- 실제 실행한 명령과 결과를 보고한다. 실행하지 않은 항목은 이유와 함께 미검증으로 표시한다.
- 로컬 검사, 정적 분석, mock·fixture 결과를 실제 외부 연동·운영 환경·실기기 검증으로 표현하지 않는다.
- 배포나 외부 데이터 변경을 단순 검증 수단으로 실행하지 않는다.
- 완료 전 최종 변경을 검토한다. Git 저장소이면 `git diff --check`, 작업 범위의 diff와 상태를 확인한다.
- 최종 보고는 변경 결과, 검증 결과, 남은 제한을 간결하게 쓴다. 문제가 없으면 불필요한 후속 작업을 만들어 제안하지 않는다.
