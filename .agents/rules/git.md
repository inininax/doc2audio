# Git·협업 규칙

- Git 저장소이면 시작할 때 현재 브랜치와 `git status --short`를 확인한다. 저장소가 아니면 그 사실을 기준으로 작업하며 Git 초기화가 된 것으로 가정하지 않는다.
- 사용자와 다른 에이전트가 만든 기존 변경을 보존한다. 충돌하는 파일은 현재 내용을 다시 읽고 담당 범위를 조율한다.
- 두 도구를 동시에 쓸 때 파일별 수정 담당을 나눈다. 같은 파일을 동시에 고쳐야 하면 별도 브랜치·worktree를 사용한다.
- 작업 인계 시 `.agents/tasks/README.md` 형식으로 목표, 변경 파일, 검증 결과, 남은 일을 남긴다. 채팅 기록이나 도구별 자동 메모리가 공유된다고 가정하지 않는다.
- `git add`는 필요한 경로를 명시한다. `git add .` 또는 `git add -A`로 다른 작업을 함께 스테이징하지 않는다.
- commit·push·merge·배포는 사용자 요청 또는 기존에 승인된 범위에서 수행한다. 보호 브랜치 변경, 브랜치 삭제, force push, 파괴적 초기화는 정확한 대상에 대한 명시적 승인을 확인한다.
- 승인된 Git 작업 직전에는 대상 ref와 상태를 다시 확인한다. 과거 인계 기록의 SHA나 완료 표시는 현재 상태의 증거가 아니다.
- `git reset --hard`, `git clean -fd`, 무관한 파일 삭제로 작업 공간을 정리하지 않는다.
