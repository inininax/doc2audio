# Material 관리자 화면 개선 검증

2026-09-13, 브라우저 웹 v0.3의 화면과 입력 흐름을 개선했다. 기존 음성 엔진과 저장 형식은 변경하지 않았다.

## 참고한 공식 디자인

- [MUI Dashboard](https://mui.com/material-ui/getting-started/templates/dashboard/): 사이드바·상단 경로·본문 패널의 구분.
- [Mantis React](https://mantisdashboard.com/free/dashboard/default): 흰 카드, 중립 배경, 간결한 상태와 정보 배치.
- [Materio](https://demos.themeselection.com/materio-mui-nextjs-admin-template-free/demo): 카드 간격과 제목·보조 정보의 위계.
- [Material 2 접근성 안내](https://m2.material.io/design/usability/accessibility.html): 대비, 터치 영역, 키보드 접근 원칙. 보관된 Material 2 문서이며 현재 Material 3 준수 인증으로 해석하지 않는다.

공식 페이지를 검색하고 실제 화면·계산 스타일을 확인했다. 템플릿 코드, 외부 폰트, 새 패키지는 추가하지 않았다. 참고 화면과 상세 메모는 `output/ui-refresh/design-references.md`, `reference-*.png`에 있다.

## 적용 결과

- 240px 사이드바와 간결한 상단 경로, 흰 패널·슬레이트 배경·파란 강조색으로 통일했다. 모바일에서는 상단 탐색으로 전환한다.
- 문서 입력과 기본 목소리·언어·배속을 먼저 보여 주고 나머지 옵션은 고급 설정으로 묶었다. 세 모델의 기존 옵션 10·9·8개를 모두 유지한다.
- 저장소 안내를 접을 수 있게 줄이고, 모델 보관함·작업 카드·상세 창의 정보 순서를 정리했다.
- 긴 작업 제목은 카드에서 3줄까지 표시하고 상세 창에서 전체를 읽는다. 좁은 화면은 본문 아래에 상세 버튼을 배치한다.
- 본문 14~15px, 보조 13px, 떠 있는 입력 라벨 실제 12px. 버튼과 입력의 실제 조작 영역은 데스크톱 최소 44px, 600px 미만 최소 48px를 적용했다. 이 수치는 프로젝트의 CSS px 기준이다.

## 고친 동작

- 메뉴를 이동하면 작성 중인 입력이 사라지던 문제: 텍스트·파일·작업 이름·음성 설정을 유지한다. 제출 실패 때 보존하고 성공했을 때만 원문 입력을 비운다.
- PDF 페이지/OCR은 PDF를 선택했을 때 표시하며 파일을 바꾸면 이전 파일의 범위를 초기화한다.
- 숫자 옵션의 오류를 안내하고 오류가 있는 고급 설정은 펼친 상태로 유지한다.
- 저장 공간 보호의 허용·거절·예외를 성공·경고·오류로 구분하고 요청 중 중복 클릭을 막는다.
- 작업 처리 오류를 상세 창 안에 표시한다. 다른 작업으로 오류가 섞이지 않으며, 실제 액션 실패는 정기 조회가 성공해도 지워지지 않는다. 액션 성공 후 일시적인 조회 실패는 다음 조회 성공 시 해제한다.
- 화면 또는 기록 페이지를 바꾸면 맨 위에서 시작한다. 상세 창만 열고 닫을 때는 기존 목록 위치를 유지한다.
- 본문 바로가기, 현재 메뉴 표시, 입력 탭/패널 연결, 고유 입력 라벨, 진행률 이름, 상세 창 이름과 포커스를 보완했다.

## 검증

실제 Chromium 브라우저에서 확인했다. 테스트 데이터로 진행률·오류·긴 제목을 확인한 결과와 실제 모델 생성 결과를 구분한다.

로컬 증거는 `output/ui-refresh/`의 화면 이미지, `after-*.json`, `form-draft-qa.json`, `drawer-error-qa.json`, `storage-qa.json`, `contrast-qa.json`, `review-*.md`, `final-build.log`, `ui-verified.mp3`에 있다.

자동화 도구의 고수준 클릭/키보드 경로에서 숨겨진 입력의 placeholder가 `null` 문자열로 바뀌는 외부 DOM 변경을 관찰했다. 앱과 MUI의 setter 기록은 없었고 같은 앱 경로를 native DOM click으로 실행하면 재현되지 않았다. 제품 우회 코드는 추가하지 않았다. 비교 근거와 정확한 원인이 미확정이라는 제한은 `output/ui-refresh/placeholder-investigation.md`에 남겼다.

검증은 로컬 Chromium과 크기 에뮬레이션 기준이며 Safari·Firefox·실제 휴대전화·전체 접근성 인증은 수행하지 않았다. 브라우저 기본 확대 단축키는 이 자동화 환경에서 배율을 바꾸지 않았다. CSS 200% 확대도 시도했지만 미디어 쿼리가 그대로여서 좁은 열이 발생했다. 이 검사는 브라우저 확대를 대신하지 않으므로 통과 근거로 사용하지 않았다. 별도로 1440px 창의 200% 확대에 해당하는 720 CSSpx 폭에서 재배치를 확인했으며, 실제 브라우저 배율 설정은 미검증이다. 빌드에는 기존 문서 처리 라이브러리를 포함한 500kB 이상 청크 경고가 남는다. 엔진 변경이 없어 이번 UI 작업에서는 Python 전체 테스트를 반복하지 않았다.

서버에는 정적 웹 파일을 배포할 수 있고 모델과 작업은 사용자 브라우저에 저장된다. 창을 닫은 동안 계산은 멈추며 같은 출처·브라우저로 다시 접속하면 저장된 구간부터 이어간다. 상세 실행 방식은 [브라우저 런타임](browser-runtime.md)을 따른다.
