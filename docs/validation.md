## v0.3 브라우저 실행 검증 (2026-09-13)

Apple Silicon macOS의 Ego Lite Chromium에서 `apps/web/dist/`를 정적 제공해 검증했습니다. 기본 웹 모드는 Python 서버에 작업을 보내지 않으며 Supertonic 3 ONNX를 브라우저 WASM에서 실행합니다. 실제 모델 결과와 단위 테스트의 mock 음성을 구분합니다.

### 자동 검사

- `npm run test:web`: **69개 통과**. IndexedDB 저장·해시 검증·실행 토큰, 다운로드 Range·중단 복구, 다중 탭 잠금, 원문 저장 후 실행, 일시정지·취소의 늦은 결과 차단, 페이지 종료 복구, 문서 추출, MP3 배속·끝부분 보존, 서비스 워커 설치 실패를 포함합니다.
- `npm run check`, `npm run format:check`, `npm run build`: 통과했습니다. 런타임/OCR 자산은 npm 설치 파일에서 복사하며 서비스 워커는 정적 자산 239개를 캐시합니다. 일부 JavaScript 묶음이 500 KB를 넘는 Vite 경고는 남습니다.
- `uv run pytest`: 기존 엔진·CLI·API **62개 통과**. `uv run ruff check .`, `uv run ruff format --check .`, `uv lock --check`, `python3 scripts/ai-env.py check`, `git diff --check`도 통과했습니다. Python 관련 사용 중단 경고는 실패와 구분합니다.

독립 리뷰에서 OCR 취소 뒤 Tesseract Promise가 끝나지 않아 대기열이 멈추는 문제와 WSOLA 배속 처리의 끝부분이 잘리는 문제를 발견해 수정했습니다. OCR 초기화·렌더링·인식 취소 및 초기화 실패 회귀를 추가했습니다. 배속은 마지막 20ms에만 신호가 있는 입력과 앞뒤 주파수가 다른 입력을 검사하고, 실제 MP3를 ffmpeg로 디코딩해 마지막 신호 보존을 확인했습니다. OCR 초기화 실패 시 SDK가 워커 핸들을 반환하지 않는 누수도 별도 소유 워커 구조로 수정했습니다. 새 출처의 테스트용 프록시에서 실제 Tesseract 언어 파일에 503 응답을 주어 오류 반환과 Chromium worker 대상 0개 복귀를 확인했습니다. 수정된 프로덕션 빌드에서도 오프라인 OCR·음성·1.25배속 MP3 신규 생성과 완료 후 worker 대상 0개를 확인했습니다. 이러한 합성 신호 검사는 음성 내용·자연스러움 평가를 대신하지 않습니다.

저장소·다운로드·대기열·PWA·UI와 TTS·문서·OCR·MP3·사용 문서를 작성자와 다른 두 리뷰어가 나누어 검토했고, 마지막 수정까지 재검증하여 미해결 지적 없이 승인했습니다.

## v0.2 모노레포·웹 검증 (2026-09-13)

Apple Silicon macOS / Python 3.12 환경에서 엔진·CLI·FastAPI 서버·Material UI 웹을 함께 검증했습니다. 아래는 이번 업그레이드 결과이며, 뒤의 2026-09-09~10 기록은 기존 문서 변환 기능의 이전 검증입니다.

### 자동 검사와 독립 리뷰

- `uv run pytest -q`: **62개 통과**. 기존 문서 추출·파이프라인 검사에 작업 저장·재시도·취소·로컬 요청 제한, 대용량 한글 입력, CLI 옵션 우선순위, 저장 경로, Supertonic 구간 보존 회귀 검사를 추가했습니다.
- `uv run ruff check .`, `uv run ruff format --check .`, `uv lock --check`, `git diff --check`, `python3 scripts/ai-env.py check`: 통과했습니다.
- `npm run check`, `npm run format:check`, `npm run build`: 통과했습니다. 초기 JavaScript 묶음 약 523 KB에 대한 Vite 크기 경고는 남습니다.
- `uv build --all-packages`: 엔진·CLI·서버 3개 패키지의 wheel/sdist 빌드가 통과했습니다. 웹은 저장소에서 빌드한 `apps/web/dist`를 서버가 제공합니다.
- 별도 리뷰 과정의 7개 구현 지적 사항을 수정하고 독립 코드 리뷰 승인을 받았습니다. Supertonic 긴 본문 끝부분과 짧은 입력 처리, 한글 multipart 크기 제한, CLI JSON 옵션 덮어쓰기, `~/` 경로 확장, 실제 모델 검증의 캐시 재사용 문제를 포함합니다.

PyMuPDF·Starlette 관련 사용 중단 경고가 관측됐으며 테스트 실패는 없었습니다. 단위 테스트의 합성 음성과 아래 실제 모델 실행은 구분합니다.

### 세 모델의 실제 생성과 오프라인 범위

`uv run python scripts/verify_models.py`는 실행마다 새 구간 작업 폴더를 사용하고 `reused_chunks == 0`을 확인합니다. 세 모델의 고정 리비전을 다운로드한 뒤, Python의 IPv4/IPv6 `socket.connect`를 차단한 상태에서 실제 음성을 새로 생성했습니다.

| 모델 | 화자 | MP3 길이 | 처리 시간 | 재사용 구간 |
| --- | --- | --- | --- | --- |
| Qwen3-TTS 1.7B MLX 8bit | Sohee | 4.39초 | 8.77초 | 0 |
| Qwen3-TTS 0.6B MLX 8bit | Sohee | 4.30초 | 6.38초 | 0 |
| Supertonic 3 ONNX | F1 | 3.92초 | 2.59초 | 0 |

`ffprobe`로 세 출력의 MP3 / 24 kHz / 모노 형식을 확인했습니다. 시간은 이 Mac의 짧은 검증 문장에 대한 관측값입니다. 결과와 리비전은 로컬 `output/upgrade/{모델 ID}-verified.json`에 남습니다.

패키지·ffmpeg·모델 설치와 웹 빌드를 완료하면 `uv run --offline doc2audio-server`로 실행할 수 있습니다. 생성 작업은 로컬 파일을 사용하고 모델 라이브러리도 오프라인 모드로 실행합니다. 웹 리소스에서 외부 폰트·CDN 요청은 관측되지 않았습니다. 새 모델 다운로드와 외부 모델 정보 링크는 인터넷이 필요합니다. 이 검증에서 Mac의 Wi-Fi 자체를 끄거나 모든 네이티브 프로세스의 네트워크를 차단한 것은 아닙니다.

Supertonic은 별도로 591자 본문의 내부 6구간을 합성해 전체 입력 보존과 마지막 구간 파형 포함을 확인했습니다. 구간별 유효 길이 합계와 결과 길이는 리샘플링 반올림 범위에서 일치했습니다. `안녕하세요.`, `마지막입니다.` 같은 짧은 입력도 실제 SDK로 정상 생성했습니다. 이번 세 모델 출력 전체에 대한 ASR 내용 비교나 화자별 청취 평가는 수행하지 않았습니다.

### 웹과 작업 수명

ego-browser에서 실제 서버와 모델로 다음 동작을 확인했습니다.

- 텍스트 입력과 파일 업로드, 모델·생성 옵션 변경, 변환 등록, 진행 상태, 완료 MP3 응답 및 브라우저 오디오 로딩을 확인했습니다.
- Qwen 변환 중 탭을 닫고 새 탭에서 작업 기록을 열어 진행 상태를 복원했습니다. 완료 후에도 같은 기록과 MP3를 확인했습니다.
- 상세 플레이어에서 듣기 배속을 선택해 실제 `audio.playbackRate`가 `1.5`로 바뀌는 것을 확인했습니다.
- 빈 별도 모델 보관함에서 Supertonic 다운로드 버튼을 눌러 실제 다운로드 완료까지 확인했습니다.
- 데스크톱과 모바일 390px 화면을 확인했으며 모바일 가로 넘침은 없었습니다.

`uv run python scripts/verify_server_runtime.py`는 실제 Supertonic 작업의 첫 구간 생성 후 서버 종료·재시작, 중단 상태 표시, 재시도 시 기존 구간 1개 재사용, 최종 완료를 검증했습니다. 실행 중 취소와 서버 재시작 후 완료·취소 기록 보존도 통과했습니다. 결과는 `output/upgrade/server-recovery-results.json`입니다.

브라우저를 닫아도 실행 중인 서버가 작업을 처리하며 SQLite 기록은 유지됩니다. 서버 종료나 컴퓨터 잠자기 중에 계속 처리하는 기능은 아닙니다. 서버를 다시 실행하고 중단된 작업을 재시도하면 검증된 구간을 재사용합니다. 검증 산출물과 모델은 로컬 전용으로 Git에 포함하지 않습니다.

고정 리비전의 Qwen3-TTS 1.7B CustomVoice MLX 8bit를 내려받아 Metal에서 실행했습니다. 기본 화자는 Sohee, 언어는 Korean입니다. 아래 결과는 실제 모델 출력이며 테스트용 톤이 아닙니다.

| --- | --- | --- |

| 한글 PDF, 날짜·금액·시간 81자 | 텍스트 추출과 낭독 순서 확인 | 16.36초 |

| 이미지로만 된 PDF | Vision 한국어 OCR, 날짜·금액·줄 순서를 원본 문구와 대조 | 16.36초 |
| 긴 문서, 699자 / 4구간 | 197·220·213·66자 분할, 실제 합성 약 44.61초 | 129.30초 |

`ffprobe`로 최종 파일이 **MP3 / 24,000 Hz / mono / 128,000 bps**임을 확인했습니다. 위 시간은 이 Mac의 관측값이며, 문서 전체 처리 시간이나 모든 입력의 속도를 보장하는 수치는 아닙니다. 반복 검증에서는 완료한 구간을 재사용했으므로, 캐시 재사용 시간을 신규 합성 시간으로 기록하지 않았습니다.

검증 당시의 로컬 결과는 `output/한국어-샘플.mp3`, `output/validation/긴 문서.mp3`, `output/validation/runtime-results.json`에 보관했습니다. `output/`은 Git 제외 대상이므로 GitHub에서 다운로드되지 않습니다. 직접 샘플을 만들려면 [README의 샘플 실행](../README.md#샘플-듣기)을, 형식별 검증을 재현하려면 아래의 `verify_runtime.py` 명령을 사용하세요.

## 음성 내용 교차 검증

별도로 학습된 **Whisper large-v3-turbo**와 **Qwen3-ASR 0.6B**를 로컬에서 실행했습니다. 정답 본문이나 관련 어휘를 인식 프롬프트에 넣지 않았습니다.

- 30초 이내의 PDF·DOCX·DOC·스캔 PDF 음성 4개는 Whisper 인식 결과에서 공백·문장부호를 제외하면 원문과 일치했습니다. 날짜·12,500원·오후 3시 30분과 마지막 문장을 포함합니다.
- 37초 샘플과 129초 긴 음성은 Qwen3-ASR로 전체 파일을 인식했습니다. 공백·문장부호와 테스트 날짜의 동등 표기를 정규화한 문자 오류율은 각각 **0.62%, 0.79%**였습니다. 일부 조사·어미·어휘 차이가 남습니다. 이것이 전부 TTS의 발음 오류인지 ASR의 인식 오류인지는 청취 평가 없이 단정하지 않습니다.
- Qwen3-ASR가 `12,500원`을 `만 이천오백 원`, `워드`를 `Word`로 쓰기도 했습니다. 따라서 이 입력의 단순 문자 오류율을 음질 저하율로 해석하지 않습니다. 표의 `세 개`/`세계` 같은 동음 표현도 두 인식기 결과를 함께 확인했습니다.
- 설치한 MLX-Audio의 Whisper 경로에서는 긴 파일의 30초 경계 누락, 마지막 수십 밀리초를 재인식하며 인사말을 덧붙이는 현상을 확인했습니다. 종료 시각·구간 WAV·다른 인식기를 대조해 TTS 오류와 구분했습니다. 재현용 검증 스크립트는 Whisper를 30초 이하 교차 점검에만 사용하고, 긴 파일은 Qwen3-ASR로 검사합니다.

실제 결과와 오디오 SHA-256은 로컬의 `output/validation/speech-verification-qwen.json`, `output/validation/speech-verification-whisper.json`에 기록했습니다. 이 보고서들도 Git에는 포함하지 않으며, 아래 ASR 검증 명령으로 새로 생성할 수 있습니다. ASR 비교는 내용 전달의 근거이며, 사람의 자연스러움 청취 평가나 모든 문서의 완전성을 보증하는 자료가 아닙니다.

## 발견해 수정한 문제

- Vision OCR이 금액을 `1 2, 5 0 0 원`처럼 나누는 문제: 명시된 한국어 단위 앞 숫자의 공백을 복원합니다. 일반 숫자 목록은 합치지 않습니다.
- OCR이 한 줄 오른쪽의 `30분입니다`를 다음 문장 뒤에 반환하는 문제: 좌표로 같은 줄을 묶고 왼쪽부터 정렬합니다. 최종 스캔 추출문을 테스트 원본 전체 문구와 비교했습니다.
- Word 병합 셀이 여러 번 읽히는 문제: 가로·세로 병합 모두 원본 셀을 한 번만 읽습니다.
- 모델이 종료하지 않고 길이 제한에 도달하는 문제: 잘린 음성을 버리고 작은 구간 또는 다른 seed로 제한된 횟수만 재시도합니다. 실제로 실패했던 78자 입력을 재실행해 자동 분할 후 17.08초 MP3 생성까지 확인했습니다.
- 중단·손상된 구간 파일: WAV 형식과 SHA-256 검증 후 재사용하며, 불완전한 구간만 다시 생성합니다. 최종 파일은 인코딩 성공 후 원자적으로 게시합니다.

## 자동 검사와 재현

`uv run pytest -q`: **37개 통과**. 한국어 PDF·DOCX, 실제 이진 DOC 변환, 실제 한국어 OCR, 잘못된 페이지·빈 문서·암호화·변경 추적, 문장 분할의 누락 방지, 발음 사전, 병합 셀·OCR 순서, 무음·잘린 생성, 중단 후 재개·손상 구간 복구·동시 실행 잠금·원본과 기존 출력 보호를 포함합니다. 파이프라인 단위 테스트의 음성은 명시된 합성 톤이고, 위 실제 모델 검증과 구분합니다.

`ruff check`, `ruff format --check`, `uv lock --check`, `uv build`, `git diff --check`, `scripts/ai-env.py check`를 통과했습니다. 기존 AI 환경 점검 스크립트는 별도 관리 파일로 두고 앱의 Ruff 대상에서 제외합니다. PyMuPDF의 SWIG 사용 중단 경고는 관측됐지만 테스트 실패는 없었습니다.

TTS 모델은 `.models/qwen3-tts-1.7b-8bit/`에 유지합니다. 선택 사항인 ASR 검증 모델은 각각 약 1.01 GB, 1.62 GB이며 일반 문서 변환에는 필요하지 않습니다. 복잡한 다단 문서·수식·모든 OCR 입력과 사용자 개인 문서는 이번 실행에서 검증하지 않았습니다.
