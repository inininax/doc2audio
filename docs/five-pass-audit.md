# 전체 코드 5회 반복 점검

검증일: 2026-09-13. Apple Silicon macOS, Python 3.12, Ego Lite Chromium.

현재 상태: 5회 반복 점검과 발견한 오류 수정·독립 검토를 완료했다. 최종 자동 검사와 빌드는 통과했고, 검토 범위에 남은 확정 결함은 없다.

엔진·CLI, 서버·작업 저장소, 브라우저 실행기·문서·오디오, 화면·배포 스크립트를 나누어 검토했다. 회차마다 담당 영역을 교대했고, 작성자의 테스트와 다른 검토자의 승인을 구분했다. 이전 개발 검증을 이번 회차에 포함하거나 같은 테스트를 다섯 번 실행하는 것으로 대체하지 않았다. 기존 미커밋 구현을 보존했으며 commit·push·외부 배포는 하지 않았다.

## 수정한 오류

| 영역 | 재현한 문제와 수정 결과 |
| --- | --- |
| Python 이어하기 | manifest가 유효 JSON이지만 객체가 아니면 예외가 났다. 구조를 확인하고 손상된 계획을 복구한다. |
| 모델 설치 | 크기가 틀린 파일을 다운로드 캐시가 계속 반환했다. 이미 존재하는 손상 파일만 강제로 다시 받는다. 연결 실패도 CLI의 명확한 오류로 전달한다. 완전 설치 상태에서는 다운로드용 여유 공간을 요구하지 않는다. |
| DOCX | 콘텐츠 컨트롤 안의 본문이 누락됐다. 원본 파일을 바꾸지 않고 본문·표 순서대로 읽는다. Word XML의 namespace 별칭에 관계없이 변경 추적을 검출한다. |
| Python 오디오 | 큰 유한 샘플을 정규화한 뒤 이전 peak를 사용해 끝부분이 잘리거나 IndexError가 났다. 정규화 후 peak를 다시 계산한다. Supertonic 응답의 실제 파형이 1샘플 반올림 허용 범위를 넘어 선언된 길이보다 짧으면 완료로 처리하지 않는다. |
| 서버 실행 | 작업 폴더 생성·DB claim 실패로 대기열이 죽거나, 실행 중 오류 뒤 자식 프로세스가 남았다. 일시 DB 오류를 재시도하고 소유 프로세스 종료를 확인한 뒤 다음 작업을 실행한다. 종료 확인 실패 시 잠금을 유지한다. |
| 서버 입력·등록 | Content-Length 없는 초과 업로드를 끝까지 임시 저장한 뒤 거절했다. 실제 수신량을 제한하고 파서 파일 정리를 확인했다. 등록과 응답 조회를 같은 DB 트랜잭션으로 묶어 후속 조회 실패로 원문만 삭제되는 경우를 없앴다. |
| 브라우저 문단·저장 | 이모지 전용 문단이 음성 변환을 중단했다. 읽을 내용이 있는 구간을 선택하며, 기존 저장 작업의 PCM 인덱스와 seed는 유지한다. 저장소의 AbortError·진행 저장 오류를 사용자 취소로 오인해 자동 재시도하던 문제를 수정했다. |
| 브라우저 자원 | 다른 탭에서 삭제한 작업의 object URL이 원래 탭에 남았다. 전체 작업 목록과 대조해 사라진 작업의 URL을 해제하며 다른 페이지에 있는 유효 음성은 보존한다. |
| 화면 | 마지막 페이지 삭제 후 빈 화면, 뒤로가기 후 오래된 최근 기록, 늦은 작업 응답으로 닫힌 상세 창이나 이전 작업이 다시 열리는 문제를 수정했다. |
| 오프라인 화면 | 실패한 설치의 부분 캐시를 정리하고 기존 사용 중인 캐시는 보호한다. 정확한 배포 경로를 기준으로 이전 캐시를 정리해 하위 앱의 캐시가 삭제되지 않도록 했다. PWA 회귀를 `npm run test:web`에 포함했다. |
| 검증 스크립트 | `verify_runtime.py`가 이전 구간을 재사용해도 실제 모델 검증 성공으로 끝났다. 실행별 새 작업 폴더와 `reused_chunks == 0` 검사로 모델을 새로 실행하도록 했다. |

## 실제 실행

실제 모델 출력과 오류 주입·단위 테스트의 mock은 구분했다. 개인 문서 대신 검증용 문서를 사용했다.

- **세 Python 모델:** Qwen 1.7B, Qwen 0.6B, Supertonic 3를 새 프로세스·새 작업 폴더에서 실행했다. Python IPv4/IPv6 연결을 막고 기존 구간 재사용 0개로 각각 약 4.39초, 4.30초, 3.92초 MP3를 생성했다. Supertonic 길이 검사 수정 후에도 새 실제 합성이 통과했다.
- **브라우저 자동 이어하기:** 실제 Supertonic 6구간 중 1구간 저장 후 탭을 닫았다. 정적 서버도 종료한 뒤 재접속해 오프라인으로 나머지를 생성했다. 시도 2회·기존 구간 1개 재사용·저장 해시 일치, 26.540375초 MP3를 확인했다.
- **브라우저 수동 일시정지:** DOCX의 콘텐츠 컨트롤을 포함한 3문장을 XML 원문과 대조했다. 1구간 후 일시정지→탭 종료→재접속에서도 일시정지 상태가 유지됐다. 이어서 실행을 누른 뒤 오프라인으로 3구간을 완성했고 기존 1구간을 재사용했다.
- **파일 검사:** 두 브라우저 MP3를 실제 저장 버튼으로 내보내고 ffmpeg 전체 디코딩에 성공했다. 브라우저 출력은 44.1 kHz·모노다.
- **마지막 웹 빌드:** 새 실제 음성 1구간·재사용 0개·약 4.25초를 생성했다. 목록의 다음 페이지로 이동해도 해당 MP3 URL이 유효했고, 다른 탭에서 이 검증용 작업을 삭제한 뒤 원래 탭의 URL이 해제되는 것을 확인했다. 이전 검증 결과와 사용자 작업은 삭제하지 않았다.
- **서버 작업 수명:** 별도 포트와 데이터 폴더에서 실제 서버 종료·재시작, PCM 재사용, 약 24.4초 MP3, 실행 중 취소, 다음 재시작 후 완료·취소 이력 보존을 확인했다.
- **정적 배포:** `/doc2audio/` 경로로 별도 빌드해 해당 경로의 서비스 워커·자산 캐시를 확인하고 정적 서버 종료 후 화면을 복원했다. 이 별도 출처에는 모델을 설치하지 않았으므로 하위 경로에서 음성까지 생성한 검사로 표현하지 않는다.
- **마지막 문서 통합 검증:** 수정된 `verify_runtime.py`를 별도 출력 경로에서 실행했다. 실제 Qwen 1.7B로 PDF·DOCX·DOC·스캔 PDF를 모두 새로 합성했고 재사용은 각각 0개였다. MP3 길이는 약 14.56초·10.12초·5.84초·14.56초다. 스캔은 macOS Vision OCR로 원문 문구와 대조했으며 브라우저 Tesseract OCR의 인식 품질을 대신하는 검사는 아니다.

오프라인 실행은 정적 서버 종료와 브라우저 CDP 오프라인 조건으로 검사했으며 시작·완료 시 `navigator.onLine === false`를 확인했다. Mac 전체 Wi-Fi를 끈 검사는 아니다. Python 소켓 차단도 모든 네이티브 프로세스의 네트워크 차단을 의미하지 않는다.

## 최종 자동 검사

- `uv run pytest`: **95개 통과**.
- `npm run test:web`: **웹 85개 + PWA 6개 통과**.
- `npm run check`, `npm run format:check`, `npm run build`: 통과.
- `uv run ruff check .`, `uv run ruff format --check .`, `uv lock --check`, `python3 scripts/ai-env.py check`: 통과.
- `uv build --all-packages`: 엔진·CLI·서버 wheel 및 sdist 빌드 통과.
- `git diff --check`와 미추적 파일을 포함한 소스·설정 82개 파일의 공백 검사: 통과. 엔진·CLI wheel 내부 소스·카탈로그·명령 진입점도 독립 검토하고 격리된 패키지로 CLI를 실행했다.

Python 의존성의 사용 중단 경고 7개와 Vite의 큰 JavaScript 묶음 경고는 남아 있다. 실패한 검사를 숨기거나 단언을 완화하지 않았다.

검증 기록과 임시 문서·MP3·JSON은 Git 제외 경로 `output/audit-five-pass/round1/`~`round5/`와 `round5-*.log`에 있다. 브라우저 모델·작업·캐시는 해당 출처의 브라우저 저장소에 남는다. 이번 점검은 별도 출처 4182·4183을 사용해 기존 4173의 사용자 기록을 보존했다.

## 범위와 제한

브라우저를 닫은 동안 계산은 멈추고, 같은 출처·브라우저 프로필에서 다시 열면 저장된 구간부터 이어간다. 최초 모델 설치와 오프라인 화면 준비에는 네트워크가 필요하다. 사이트 데이터 삭제나 다른 브라우저·PC로의 이동에 대한 자동 복구·동기화는 제공하지 않는다.

이전 [브라우저 검증](validation.md)에 기록된 한국어 OCR 오인식은 남아 있다. 모든 문서 레이아웃·언어·화자·모바일·브라우저 조합을 검증한 것은 아니며, 이번 출력 전체의 ASR 대조나 사람의 자연스러움 청취 평가는 하지 않았다. 다섯 차례 점검은 검토 범위의 오류를 찾고 수정한 근거이며 모든 입력에서 버그가 없다는 보증은 아니다.
