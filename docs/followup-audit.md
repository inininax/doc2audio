## 실제 실행

- 설치된 Supertonic 3로 장식 단락 문제를 수정 전후 실행했다. 수정 후 신규 합성은 정상 2구간·캐시 재사용 0, 기존 캐시에서 다시 실행하면 정상 2구간을 재사용했다. 원래 PCM SHA-256은 같았으며 양쪽 MP3 전체 디코딩이 통과했다.
- 실제 Chromium에서 지연 응답 fixture로 상세 상태 덮어쓰기와 이전 페이지 목록 노출을 수정 전후 확인했다. 재시도 후 최신 상태를 유지하고, 2쪽 응답 전에는 이전 카드 대신 로딩을 표시한다.
- 같은 UI 검증에서 메뉴 이동·실패 후 텍스트와 제목 보존, 잘못된 배속의 등록 차단, 성공 후 입력 초기화, 파일과 PDF 페이지 범위 보존을 확인했다. 390px 화면의 가로 넘침도 없었다.
- 최종 프로덕션 빌드와 실제 Supertonic 3 모델 18개 파일로 브라우저 작업을 실행했다. 12구간 중 6구간을 저장한 뒤 앱 탭을 닫았다. 닫힌 동안 PCM과 다음 작업의 대기 상태는 유지됐고, 다시 열면 6구간을 재사용해 102.5초 MP3를 완성했다. 기존 6구간과 최종 13구간(대기 작업 포함)의 실제 PCM SHA-256을 검증했다.
- CDP로 브라우저 네트워크를 차단한 상태에서 새 한국어 문서를 합성해 8.2초 MP3를 저장했다. 합성 전후 모두 navigator.onLine=false이고 캐시되지 않은 요청이 실패했다. 캐시된 화면의 재로드도 확인했다. 브라우저 재개·오프라인 신규 MP3 모두 ffmpeg 전체 디코딩이 통과했다. 이는 브라우저 네트워크 에뮬레이션이며 운영체제 전체의 네트워크를 끈 시험은 아니다.
